# Arachne Code Reviewer

Meta-prompt for reviewing Godot 4.x GDScript code generated for Project
Arachne. Load this skill when you need to review AI-generated code, validate
that new code follows project conventions, or generate corrected versions.

Also load `godot-gamedev` and `ponytail-review` for their
domain-specific rules — this skill covers Arachne-specific conventions
not covered by those general skills.

## Context & Constraints

Project Arachne: Godot 4.6.3, CharacterBody2D platformer brawler.
Key conventions:

- **Typed GDScript 2.0:** Static types everywhere, `@export` for tunables
- **Physics:** Screen-space gravity/jump (NOT `up_direction`-relative)
- **Surface sticking:** `floor_max_angle = PI` for wall/ceiling traversal
- **Surface detection:** `get_last_slide_collision()` for contextual controls
- **Ponytail active:** Simplest solution that works, no over-engineering
- **Tests:** `godot --headless -s tests/test_player.gd`

## When to Load This Skill

- Reviewing GDScript generated by another agent/LLM
- Generating GDScript and need project-specific constraints
- Validating code before committing to the repo
- Code Review Agent in the multi-agent pipeline
- Fixing test failures or physics bugs

## Step 1: Identify What's Being Reviewed

Classify the code:
- **New component:** Full file review against all rules
- **Patch/diff:** Targeted review of changed lines only
- **Test failure:** Root-cause analysis against physics/signal rules
- **Generated code:** Full audit (AI code has characteristic bugs)

## Step 2: Run the Arachne Audit Checklist

### Physics Rules (load godot-gamedev for details)

- [ ] Gravity is screen-space: `velocity.y += gravity * delta`
- [ ] Jump is screen-space: `velocity.y = -jump_impulse`
- [ ] NOT using `up_direction`-relative vector math
- [ ] `floor_max_angle = PI` is set
- [ ] `is_on_floor()` guard on gravity (prevents pulling off surfaces)
- [ ] Friction prevents ice-sliding when stuck to walls
- [ ] Coyote time + jump buffer are present and non-overlapping
- [ ] Variable jump height via `jump_cut_multiplier`

### Arachne-Specific Rules

- [ ] Uses `get_last_slide_collision()` for surface type detection (not raycasts)
- [ ] Contextual actions keyed off collision surface properties, not hardcoded state machines
- [ ] No spider/insect references in code (mechanical/web theme only)
- [ ] `@export` variables for all tunables (no magic numbers)
- [ ] Signal connections use `signal` keyword, not string-based connect
- [ ] `class_name` present for reusable components
- [ ] Docstring with usage example on every class

### Ponytail Rules (load ponytail-review for details)

- [ ] No premature abstraction (single-use class, factory pattern, unnecessary interface)
- [ ] No dead code or commented-out blocks
- [ ] No over-configuration (unused `@export` vars, unused signals)
- [ ] Simplest data structure that works (array vs custom class, dictionary vs resource)
- [ ] Functions are short and do one thing

### Godot Best Practices

- [ ] `_ready()` for scene setup, `_process()` for per-frame non-physics, `_physics_process()` for movement
- [ ] No `$` shorthand — use `@onready var node := $Path/To/Node as NodeType`
- [ ] Typed arrays: `var enemies: Array[Enemy] = []`
- [ ] Null checks on `get_node()` calls
- [ ] No `yield` — use `await` (Godot 4.x)
- [ ] No `owner` hacks for cross-scene references — use signals or autoloads

## Step 4: Common AI-Generated Code Bugs to Flag

### 1. Mixed physics models
AI often generates screen-space gravity but `up_direction`-relative jump,
or vice versa. Flag immediately — this causes frame-order-dependent bugs.

### 2. Missing `is_on_floor()` guard
AI generates gravity that applies every frame, pulling the player off
walls/ceilings despite `floor_max_angle = PI`. Gravity must be guarded.

### 3. String-based signals
AI defaults to `connect("signal_name", ...)` (Godot 3.x pattern).
Godot 4.x uses `signal_name.connect(_on_signal_name)` or declarative signals.

### 4. Over-engineering surface detection
AI tends to generate raycast arrays, state machines, and complex
surface classifiers when `get_last_slide_collision()` + a simple
property check on the collider is sufficient.

### 5. Magic numbers
AI hardcodes values (120.0 for jump, 300.0 for speed) instead of
using `@export var`. Every tunable must be `@export`.

### 6. `yield` instead of `await`
AI trained on Godot 3.x documentation uses `yield`. Godot 4.x
replaced it with `await`. Reject immediately.

### 7. Premature class extraction
AI loves to create `BaseEnemy`, `EnemyFactory`, `EnemyStateMachine`
when a single `Enemy` class with a dictionary state map would suffice.

### 8. class_name breaks in headless test mode
Godot 4 `class_name` registration does NOT propagate through `load()`
calls when running headless (`--headless -s test.gd`). A test file
that does `load("res://scripts/enemies/boss_base.gd")` will fail
to resolve `BossBase` even though `class_name BossBase` is declared.

**Workaround:** Use path-based `extends` in files that must be
`load()`-ed in tests, while keeping `class_name` for editor/production:
```gdscript
# lava_knight_boss.gd
extends "res://scripts/enemies/boss_base.gd"
class_name LavaKnightBoss
```
The test can then `load()` the file path without needing `class_name`
resolution. See `test_lava_knight_boss.gd` for a working example.

## Step 5: Test Compatibility

Generated code must be compatible with the project test suite.
Check that:
- `class_name` is set (required for test imports)
- No `@tool` or editor-only code in runtime scripts
- No reliance on project-specific autoloads without documenting them
- Signals are declared (tests often connect to signals)
- Public API methods exist for test access (test-only methods documented)

Run verification after review:
```bash
godot --headless -s tests/test_player.gd
```

## Pitfalls

### Reviewing without loading godot-gamedev
The physics rules in this skill are a summary. For detailed sign-error
analysis, surface-traversal edge cases, and coyote-time/jump-buffer
overlap bugs, load `godot-gamedev`.

### Reviewing without loading ponytail-review
The ponytail rules here are abbreviated. For the full over-engineering
audit (factory patterns, premature interfaces, dead code, over-configuration),
load `ponytail-review`.

### Accepting generated code without running tests
AI-generated GDScript often compiles but fails at runtime (signal
mismatches, null references, physics sign errors). Always run the
test suite.

### Not checking test_player.gd compatibility
The test file uses specific class names and method signatures. If
generated code renames classes or changes method signatures, tests
break silently on next CI run.
