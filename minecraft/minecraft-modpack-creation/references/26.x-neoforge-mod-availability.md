## Inspecting a Modrinth MODPACK (not a mod) — keyless API recipe
- `/v2/project/<slug>` → title, `game_versions`, `loaders`.
- `/v2/project/<slug>/version` → filter by `game_versions` + `loaders`. A pack may have a single
  NeoForge release while its Fabric line is many versions ahead (BA+ 1.39 NeoForge/26.1.2 vs 1.56
  Fabric/1.21.11 — the NeoForge port lags badly; don't assume "latest" is your loader).
- **GOTCHA:** `/v2/version/<id>` `files[]` holds ONLY the main `.mrpack`; the real mod list is in
  `dependencies[]` as opaque `{project_id, version_id}` pairs. Download the `.mrpack` and read
  `modrinth.index.json` for the authoritative answer:
  - `dependencies` = exact loader pin (e.g. `{"minecraft":"26.1.2","neoforge":"26.1.2.99"}`)
  - `files[]` = the true file list (`mods/*.jar` + resourcepacks/shaderpacks) with download URLs
  - `overrides/` = configs + extra mods (`overrides/mods/`) + client-only files (options.txt, shaderpacks)

## FTB Quests authoring (26.1.2 = ftb-quests 26.1.2.9, JSON5 storage)
- Files live in `config/ftbquests/quests/`: `chapter_groups.json5`, `data.json5`, `chapters/*.json5`,
  `lang/en_us/chapter.json5` (chapter titles), `lang/en_us/chapters/<filename>.json5` (holds
  `quest.<ID>.title` + `quest.<ID>.quest_desc`). Titles/descriptions go in LANG files, NOT inline.
- `data.json5` has REQUIRED fields — `BaseQuestFile.readData` calls `Optional.orElseThrow` and throws
  `NoSuchElementException: No value present` at startup if any is absent. Required: `version`,
  `default_reward_team`, `default_consume_items`, `default_quest_shape`, `default_quest_disable_jei`,
  `drop_loot_crates`. Just copy Evo 2's full data.json5 schema (add `icon`, `tags`, `presets`, etc.).
- Reward types: `"xp"` (XP points), `"item"` (needs `item:{id,count}`), `"currency"` (FTB coins).
  Set `team_reward: false` on rewards for per-player claims (friends servers).
- Verify with a headless server boot and grep the log for
  `Loaded N chapter groups, N chapters, N quests, N reward tables` — 0 errors = success.
  (Chapters/quests reference each other via 16-hex `id` strings in `dependencies` arrays.)

## Client-pack assembly pitfalls (verified Oct 2026, evo2-tech build)
- **Voxy is Fabric-only for 26.1.2** (`0.2.18-beta`, loader=`fabric`). No NeoForge build. The NeoForge
  long-render-distance answer is **Distant Horizons** — on Modrinth as slug `distanthorizons`
  (NOT `distant-horizons`), e.g. `3.3.3-26.1.2` ships as a combined fabric+neoforge jar. Shaders on
  26.1.2 = **Iris + Sodium** (Oculus/Embeddium are 1.21.1-only); DH+Iris needs a DH-aware shaderpack.
- **Client-side required deps hide from server mods/ folders.** Oritech 2.0.0-exp7 declares `athena`
  with `side="CLIENT"`, so evo2's *server* mods/ omits it — but a *client* pack MUST add `athena`
  (Modrinth slug `athena-ctm`, `4.7.3` for 26.1.2) or the client crashes on launch. When curating a
  client pack from a server mods/ folder, resolve `side="CLIENT"` deps separately (server installs skip them).
- **JiJ (jar-in-jar) deps look "missing" to naive checks.** endercore (bundled in enderio), apollib (in
  tectonic), ae2addonlib + ae2wtlib_api (in AdvancedAE/ExtendedAE/ae2wtlib) live under `META-INF/jarjar/`
  — no separate jar needed. Check `jarjar/` before assuming a dep is truly absent.
- **mezz_config is a GAMELIBRARY** (declared via MANIFEST `FMLModType: GAMELIBRARY`, not mods.toml) —
  parsers that only read mods.toml/fabric.mod.json miss it; it's fine and satisfies JEI's dep.
- **Dependency-verification technique (catches what version-facet checks can't):** parse each jar's
  `META-INF/neoforge.mods.toml` (or `mods.toml` / `fabric.mod.json`) for declared `modId` + all
  `type="required"` dep modIds, cross-check against the declared set, then confirm any stragglers are
  JiJ (in `jarjar/`) or game libraries. Found-and-fixed 9 real missing libs this way on the first build. Reusable script: `scripts/depcheck.py`.
- **Verify a Modrinth/CF-downloaded mod's NeoForge MINIMUM patch against your PINNED version — before shipping.** Just Zoom (`just-zoom` on Modrinth, NOT `justzoom`) builds 3.0.0 *and* 3.0.1 for MC 26.1.2 both declare `neoforge >= [26.1.2.114,)` in `META-INF/neoforge.mods.toml`, but evo2-tech pins **26.1.2.109** (to match the Evo 2 server) → `Mod justzoom requires neoforge 26.1.2.114 or above` → hard launch fail. This surfaces ONLY on the client (Just Zoom is client-only, so a server smoke test never loads it — it slipped through). Fix: for any mod NOT curated from the version-matched source server, read the jar's `neoforge.mods.toml` `[[dependencies.<id>]] modId="neoforge" versionRange="[...]"` and compare against your pin; bump is wrong when it desyncs you from the server, so drop the mod instead. (Just Zoom was removed from evo2-tech for exactly this reason — final client build is 174 jars, 9 client-only.)

## Puffish Skills + Paxi (skill tree) — evo2-tech, Oct 2026
- **Puffish Skills has NO built-in tree** — it's a framework; the tree is a DATAPACK loaded by a
  global datapack loader. **Paxi** (YUNG, Modrinth `paxi`) has a 26.1.2 NeoForge build
  (`Paxi-26.1.2-NeoForge-6.1.0.jar`), reads datapacks from `config/paxi/datapacks/`.
- **Do NOT reuse a kitchen-sink pack's Puffish tree in a lean pack.** FTB Evo 2's tree (in
  `datapacks/ftb/data/puffish_skills/`) references `ftb:*` custom attributes + a dozen absent mods
  (apothic_attributes, paraglider, combat_roll, artifacts, reliquary, neovitae, irons_artifice, anima,
  witchery, occultism, roots) AND the `ftbevolution` texture pack (frames) + `ftb` datapack (lang keys)
  → every skill spams `Unknown item/attribute` and titles render as raw `skill.ftb.*` keys. Build fresh.
- **Puffish datapack format** (per category under `data/puffish_skills/puffish_skills/`): `config.json`
  (category id list), `categories/<id>/{category.json, skills.json, definitions.json, connections.json,
  experience.json}`. **`background` is REQUIRED** in category.json
  (`{"texture":"<ns>:<path>","width":16,"height":16,"position":"tile"}`; a vanilla texture like
  `minecraft:textures/gui/options_background.png` works — Puffish ships no default). `title`/`description`
  take `{"text":"..."}`; `frame` is optional. Rewards:
  `{"type":"puffish_skills:attribute","data":{"attribute":"<attr>","value":X,"operation":"addition|multiply_base"}}`.
  Safe attributes: vanilla flattened (`minecraft:max_health`, `minecraft:attack_damage`,
  `minecraft:movement_speed`, `minecraft:armor`, `minecraft:armor_toughness`…), `puffish_attributes:*`
  (magic_damage, magic_resistance, mining_speed, sword_damage, axe_damage, fortune, fall_reduction,
  sprinting_speed, resistance, damage_reflection, life_steal, jump, stamina…), `arsmagicalegacy:*`
  (max_mana, mana_regeneration, max_burnout). Simplest XP source that works:
  `{"type":"puffish_skills:deal_damage","data":{"variables":{"damage":{"operations":[{"type":"get_dealt_damage"}]}},"experience":[{"expression":"damage * 0.5"}]}}`.
  Verify: `puffish_skills: Data pack loaded successfully` + zero `Unknown item/attribute` warnings.
- **Thaumaturge wild-portal rarity:** `config/thaumaturge-common.toml` → `crimsonPortalRarity`
  (higher = rarer, 0 = off; mod default 500, Evo 2 used 5000). Set high (e.g. 50000) for new-player-friendly.

## Discovering a pack's client-only mods (no client manifest needed)
The FTB App API (`api.modpacks.ch/public/modpack/{id}`) rejects the numeric FTB App ID ("Modpack id
not valid" — backend moved to CreeperHost v1). Don't chase it. The running server's **`config/`
directory is an authoritative source of the FULL mod list (client + server)**: packs ship
`overrides/config/` pre-generated configs, which get copied to the server even for CLIENT-ONLY mods
that never load there. So `ls config/` reveals client-only perf/QoL mods (`sodium-mixins.properties`,
`iris-excluded.json`, `immediatelyfast.json`, `entityculling.json`, `appleskin-client.toml`,
`MouseTweaks.cfg`, …) that the server `mods/` folder omits. Grep for `-client.` or
`sodium|iris|entity|mousetweaks|appleskin` to enumerate them. FTB Evo 2's client ships Sodium + Iris +
ImmediatelyFast + Entity Culling (+ AppleSkin/Mouse Tweaks/Just Zoom) but NOT Distant Horizons.

## Split builds: client/ + server/ folders
When the user wants both, build `client/mods/` (everything) and `server/mods/` (shared only), keep a
`client-only-mods.txt`, and verify the split with a SORTED diff — `comm`/`diff` silently misreport on
case-insensitive vs case-sensitive sort order, so force `LC_ALL=C sort`:
  diff <(ls client/mods | LC_ALL=C sort) <(ls server/mods | LC_ALL=C sort) | grep '^<'
The only `^<` lines must be the intended client-only jars.

## FTB Evo 2 client perf stack + client-inspection technique
FTB Evolution 2's *client* ships **Sodium + Iris + ImmediatelyFast + Entity Culling** (+ AppleSkin, Mouse
Tweaks, Just Zoom, Better Advancements, ToroHealth, Overflowing Bars, CleanView) — **no Distant Horizons,
no Oculus/Embeddium** (those are 1.21.1-only). A client build that matches evo2 = that stack; DH is an
optional extra on top.

**Finding client-only mods without the FTB API:** `api.modpacks.ch/public/modpack/{id}` rejects the FTB
App's numeric IDs (`"Modpack id not valid"` for FTB_MODPACK_ID=135; the search endpoint returns
`"Search term too short"`). Don't fight it — inspect the server's `data/config/` dir instead: the pack's
`overrides/` copy configs for client-only mods to the server too, so client mods show up as
`*-client.toml`, `sodium-mixins.properties`, `iris-excluded.json`, `entityculling.json`,
`immediatelyfast.json`, `MouseTweaks.cfg`, `appleskin-client.toml` — even though their jars never load
server-side. Grep the config dir for those suffixes to reconstruct the client mod list.

When the user wants both a client and server build: `client/mods/` = everything; `server/mods/` = same
minus the client-only render/QoL mods (Sodium, Iris, DH, ImmediatelyFast, FlickerFix, Athena, Entity

case-sensitive-vs-locale sort makes `comm`/`diff` report phantom differences.
